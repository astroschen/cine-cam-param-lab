## 三个关键设计决策

**1. 参数不是滑块，是「可溯源的知识单元」**
每个参数都有中英文名、语义说明、渲染绑定、提示词 token。提示词里的每个词条都能溯源到具体参数值——鼠标悬停提示词里的 `shallow depth of field` 会高亮「光圈 f/1.4」滑块。这一条是产品与「提示词抄写板」的根本区别。

**2. 平台切换是重新编译，不是换皮**
参数 → 平台无关的语义 token 表 → 各平台渲染器。同一组参数在 MJ 是 `--ar 16:9 --s 250` 的英文短语流，在即梦是中文自然语言，在可灵是「【镜头】【画面】【光影】」结构化分块，在 Veo 是连贯段落。新增平台只需实现一个接口。

**3. 诚实标注保真度**
精确焦距毫米数、精确色温这类参数 AI 模型通常不敏感。工具在参数上打「≈」标记，在提示词面板显示保真度徽章（高 78% / 中 17% / 低 5%）。不假装能精确执行 `f/1.4`。

## 架构要点

- **Vue 3 + TypeScript + Vite**，状态用 Pinia，无 UI 组件库、无图表库
- **原生 WebGL2 五段管线**：景深近似 → 主调色 → 分离模糊泛光 → 合成（色差/暗角/光斑）→ 颗粒锐化
- **扁平键设计**：`'lens.aperture'` 而非嵌套对象，天然对应 URL 编码与 uniform 映射
- **渲染分辨率自适应**：拖动时 0.75×，停止 150ms 后 1.0× 重渲——保证 1080p 参考图下稳定 60fps
- **URL 分享**：参数 JSON → deflate → base64url，约 540 字符；图片不入链接

---

## 核心风险

预览是「感知模拟」而非物理光线追踪，景深用径向梯度近似，与 AI 实际出图必然存在偏差。定位上把它当作**提示词校准器**而非效果保证器，并在 UI 中明示。
