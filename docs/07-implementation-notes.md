## 二、核心架构

### 2.1 参数 → 提示词的三层编译

```
ParamValues (扁平键 'lens.aperture')
    ↓ 逐项求值：range 查 segments / select 查 options / tags 展开
SemanticToken (en 文本 + category + strength)
    ↓ 去重合并 + 冲突消解（Look/参数 > mood 标签）
TokenBuckets (11 个语义分类桶）
    ↓ 剪枝（精简/标准/详尽）
平台渲染器 → body + flags + negative + tech
```

**平台切换是重新编译，不是换皮** —— 五个平台各有独立的语法结构：

| 平台 | 语法特征 |
|---|---|
| Midjourney | 短语流 + `--ar / --style raw / --s / --v` 后缀 |
| Stable Diffusion | 括号权重 `(kw:1.3)` + 独立负面提示词字段 |
| 即梦 | 中文自然语言长句，主体 → 环境 → 光影 → 风格 |
| 可灵 | `【镜头】【画面】【光影】【风格】` 分块 |
| Veo | 连贯英文散文段落 |

### 2.2 渲染管线

源纹理 → 景深(DOF) → 主调色(Grade) → ┬ 高光提取 → 分离模糊 → 泛光 ┐
                                    ├ 光晕(Halation) ─────────────────┤→ 合成 → 颗粒/锐化 → 屏幕

- 渲染分辨率自适应：拖动时 0.75×，停止 150ms 后 1.0× 重渲
- 全程在 **sRGB 空间**运算（不做二次编码）
- 景深用径向梯度 + 垂直梯度近似深度，不做物理光线追踪（UI 中常驻「非物理光线追踪」徽章）

## 三、本轮修复的真实 Bug

### 3.1 导入图片上下颠倒（最严重）

**现象**：程序化场景显示正常，但拖拽导入的 PNG 在对比模式下上下左右全反。

**根因**：`UNPACK_FLIP_Y_WEBGL` 这个 WebGL 标志**对 Canvas 有效、对 ImageBitmap 无效**。
导入路径走 `createImageBitmap`（ImageBitmap），场景路径走 Canvas，两条路的方向行为不一致。

**修复**：不再依赖该标志，改为 CPU 侧把源图翻转绘制到统一 Canvas
（`renderer.ts` → `flipSourceVertically`），WebGL 只接收 Canvas。

**配套调整**：顶点着色器去掉 `0.5 - aPos.y * 0.5` 翻转。原因是管线共 8 次绘制
（7 次 FBO + 1 次屏幕），FBO 往返本身已产生偶数次翻转，再叠加一次会变成奇数。

**验证方式**：构造只在一角画色块的测试图 → 截图肉眼确认 → readPixels 像素级量化。
修复前红块落在右下角，修复后落在右上角，与原图一致。

### 3.2 焦距与镜头性格自相矛盾

`lens.lensType` 默认 standard 产出硬编码 token "50mm lens"。当用户把焦距拉到 110mm 时，
提示词正文同时出现 "50mm lens" 和技术参数块的 "110mm"，互相打架。

修复：`lensStandard` token 去掉硬编码毫米数；新增 `focalFamily` 冲突组，
优先级为 **焦距 > 镜头性格 > 视野宽度**。

### 3.3 Stable Diffusion 嵌套括号权重

输出 `((110mm f/2.8:1.2):1.2)` —— 光学参数被提前加权，末尾又统一加权一次。
修复：只推原文，加权统一在末尾 `parts.map` 完成。

### 3.4 精确焦距未进正文

MJ / SD / 即梦 正文里没有精确焦距毫米数，只有 Kling/Veo 有。
修复：5 个平台正文统一输出 `110mm f/2.8`（即梦用中文句式）。

### 3.5 此前轮次修复（摘要）

- 负面词引擎语义方向完全反转（命中时从负面词"移除"单词）→ 重写为 `add`/`suppress` 双语义
- 曝光被平方（CPU `2**EV` + shader `pow(2,EV)`）→ CPU 只传 EV 档数
- sRGB 二次编码导致整体发灰 → 移除末端 `linearToSrgb()`
- 白平衡把 5600K 当作暖偏 → 改以 5600K 为中性零点做相对偏移
- 自然饱和污染中性灰（品红/红色）→ 加 `hsv.y > 0.001` 守卫并改乘法
- 分离色调过曝偏橙 → tint 去均值 + 新增 `look.splitAmount` 强度参数
- 「原图」对比图层始终空白 → 统一 ref 名并补 `setOriginal()` 绘制

## 七、给后续维护者的提醒

**WebGL 方向问题不能靠推理，必须用带唯一标记的图做视觉验证。**
本轮定位 ImageBitmap 的 `UNPACK_FLIP_Y` 失效花了十余个探针脚本。
纯 readPixels 推理极易因 y 轴语义（readPixels 的 y=0 是缓冲区第一行，
而对默认帧缓冲来说是屏幕底部）而自我误导 —— 我在这个坑里绕了很久。

有效路径：**① 构造只在一角画色块的测试图 → ② 截图肉眼确认 → ③ 再用 readPixels 量化。**
