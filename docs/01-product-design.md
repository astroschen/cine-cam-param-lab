# CineCam Param Lab · 产品设计文档

> 影视相机模拟器 —— 把「调参直觉」变成「可执行的 AIGC 提示词」
> 版本 0.1 / 2026-10-30

---

## 1. 产品定位

### 1.1 一句话定义

**CineCam Param Lab 是一个纯前端、离线的「电影镜头参数工作台」：用户拖动滑块调整摄影机与后期参数，右侧实时生成可直接喂给 AIGC 模型的提示词。**

### 1.2 它解决的问题

创作者在用 AI 生成影视级画面时，脑子里有一整套电影语言（`f/1.4 浅景深`、`500T 夜戏`、`逆光轮廓光`、`柔和高光`、`35mm 轻微透视`），但 AI 只吃自然语言描述。中间这段「翻译」全靠个人经验，且**不可复用、不可精确、不可教学**。

现有工具的缺口：
- 胶片模拟 App（如 Halide / VSCO）有真实的图像处理，但**不产出提示词**，且参数是相机厂家的黑盒逻辑。
- 提示词工具（如 PromptHero / 提示词库）有文案，但**没有参数体系**，用户只能抄别人的形容词，不知道它对应什么光学条件。
- 没有工具把「光学参数 → 视觉语义 → 提示词 token」这条链路打通。

### 1.3 核心价值主张

| 维度 | CineCam Param Lab 的做法 |
|---|---|
| **所见即所得** | 滑块拖动 → Canvas 实时渲染出对应的画面效果（色彩/颗粒/光晕/景深模拟） |
| **参数即知识** | 每个参数都有教学注解，说清「它改变了什么、对应画面什么感觉」 |
| **参数即提示词** | 参数自动编译为多平台原生语法的提示词，含负面提示词 |
| **零门槛、零隐私** | 纯前端，图片不离开浏览器，无账号无上传 |
| **可复现** | 参数档案可导出 JSON、可分享为 URL 链接 |

### 1.4 非目标（明确不做）

- ❌ 不做图片生成/调用 AIGC API（只产出提示词，生成交给用户自己的平台）
- ❌ 不做视频剪辑、素材库、账号体系
- ❌ 不做精确的物理级光学成像求解（是「感知模拟」，不是「光线追踪」；景深用径向模糊近似）
- ❌ 不做服务端存储与协作

## 2. 目标用户与场景

### 2.1 三类用户

| 用户类型 | 画像 | 核心诉求 | 使用深度 |
|---|---|---|---|
| **A. AI 影像创作者**（主力） | 接单/自媒体，用 MJ、可灵、即梦产图产视频 | 快速把「电影感」翻译成模型听得懂的词，并验证效果 | 全参数 + 精细提示词 |
| **B. 学习者** | 电影学院学生 / 自学调色 | 理解参数之间的因果关系，学会有意义的参数组合 | 预设起步 + 参数注解 |
| **C. 导演/摄影指导** | 前期筹备、分镜沟通 | 用一个链接把「我想要的画面」精确传达给团队 | 导出档案 + 分享链接 |

### 2.2 核心用户旅程

```
进入站点
   ↓
[无参考图] → 使用内置「测试场景」或拖入自己的参考图
   ↓
选择预设（可选）：如「夜戏 · 霓虹」「纪实 · 阴天」「商业 · 柔光」
   ↓
逐组调参：镜头 → 曝光 → 影调 → 色彩风格 → 质感光效 → 布光 → 构图 → 氛围
   │        （每拖一次，预览实时更新，右侧提示词同步增长/替换词条）
   ↓
切换目标平台（Midjourney / SD / 即梦 / 可灵 / Veo …）
   ↓
微调提示词：拖动词条权重 / 增删词 / 切换详略级别
   ↓
复制提示词 / 导出参数档案 JSON / 分享链接
```

### 2.3 三个关键设计时刻（North Star Moments）

1. **「原来 f/1.4 就是这个感觉」** —— 首次拖动光圈滑块，预览背景散开成奶油虚化，右侧新增 `shallow depth of field, creamy bokeh`。
2. **「它懂可灵」** —— 切到可灵平台，提示词从 MJ 的 `--ar 16:9 --style raw` 语法，自动重写为中文分镜式描述 + 时长/帧率/运镜参数。
3. **「一链接传给同事」** —— 分享链接打开后，所有参数、预设、目标平台、提示词版本完全一致。

## 3. 信息架构

### 3.1 三栏工作台布局

```
┌───────────────────────────────────────────────────────────────────────────┐
│ TOPBAR  logo │ 导入参考图 │ 预设库 │ 撤销/重做 │ 平台切换 │ 导出档案      │
├──────────────┬────────────────────────────────────┬───────────────────────┤
│ 参数侧栏      │        预览画布（视觉核心）          │  提示词输出面板        │
│ (可折叠)     │                                    │                       │
│              │  ┌──────────────────────────────┐  │  ┌─────────────────┐  │
│ ▸ 摄影机/机身 │  │                              │  │  │ 平台 Tab 组      │  │
│ ▸ 镜头       │  │      参考图 / 测试场景        │  │  │ MJ SD 即梦 可灵  │  │
│ ▸ 曝光       │  │                              │  │  ├─────────────────┤  │
│ ▸ 影调       │  │   ← 拖动分界线做 Before/After → │  │  │ 提示词正文        │  │
│ ▸ 色彩风格    │  │                              │  │  │ (高亮来源词条)   │  │
│ ▸ 质感/光效   │  └──────────────────────────────┘  │  ├─────────────────┤  │
│ ▸ 布光       │  HUD:  35mm  f/1.4  1/50  ISO800    │  │ 负面提示词        │  │
│ ▸ 构图/镜头语言│  ▣ 缩放  ▣ 网格  ▣ 波形  ▣ 全屏    │  ├─────────────────┤  │
│ ▸ 氛围/时间  │                                    │  │ 技术参数块        │  │
│ ▸ 情绪标签    │                                    │  │ 复制 / 导出 / 分享│  │
└──────────────┴────────────────────────────────────┴───────────────────────┘
                    底部抽屉：参数说明 / 曲线编辑器（M6）/ 预设抽屉
```

### 3.2 响应式策略

| 断点 | 布局 |
|---|---|
| ≥1440px | 三栏并列（侧栏 320px / 画布 flex / 面板 400px） |
| 1024–1439px | 三栏但侧栏收窄至 280px，面板 340px |
| 768–1023px | 画布置顶全宽，侧栏与面板变为左右滑出抽屉，Tab 切换 |
| <768px | 单列纵向堆叠：预览（sticky 顶部）→ 滑块 → 提示词；提示词面板改为底部弹出 |

移动端优先级：**滑块 > 预览 > 提示词**，因为参数是这个工具的「发动机」。

## 4. 核心功能清单（按优先级）

### P0 —— MVP 必须有

| # | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| P0-1 | 参考图导入 | 拖拽 / 点击 / 粘贴导入；本地 `createImageBitmap` 解码，不上传 | 1 张 4000px JPEG 导入 < 1s 解码，内存占用可控 |
| P0-2 | 内置测试场景 | 无图时提供 3–5 个程序化场景（灰阶渐变、色彩条、人像剪影、逆光轮廓），保证「无素材也能用」 | 首次进入立即有可视反馈 |
| P0-3 | 分组参数滑块 | 8 大组、50+ 参数，统一组件（滑块/下拉/开关/色板） | 所有参数可调，URL 可还原 |
| P0-4 | 实时预览渲染 | WebGL2 管线：曝光/WB/影调/色彩/颗粒/泛光/光晕/色差/暗角/锐化 | 拖动滑块到预览刷新 ≤ 16ms（1080p 参考图） |
| P0-5 | Before/After 对比 | 画布内可拖动分割线，实时对照 | 分界线可拖、可键盘操作 |
| P0-6 | 参数→提示词编译 | 参数映射为中英双语语义 token，实时更新 | 任一参数变化，提示词 ≤ 100ms 更新 |
| P0-7 | 多平台输出 | MJ / SD / 即梦 / 可灵 / 通用，语法各异 | 同一组参数在 5 个平台输出均语法正确 |
| P0-8 | 复制与导出 | 一键复制提示词 / 导出 JSON 参数档案 / 复制分享链接 | 复制含负面词与技术参数块 |
| P0-9 | 预设库 | 内置 ≥24 个精选预设（按风格分组），可另存自定义 | 预设可叠加「软重置」 |

### P1 —— 增强

- 曲线编辑器（RGB 曲线 / HSL）
- 撤销/重做（参数级历史，≥50 步）
- 提示词词条权重微调（`关键词:1.3`）
- 提示词详略三档（精简 / 标准 / 详尽）
- 参数「影响说明」悬浮卡片 + 术语表
- 视频模式（时长 / 帧率 / 运镜强度 / 首尾帧）
- 参数覆盖率面板（显示哪些参数被成功表达、哪些被模型忽略）

### P2 —— 进阶

- LUT（.cube）导入
- 自定义预设分享市场
- 批量参数扫描（自动生成一组候选提示词）
- 与 AIGC 平台的「结果回灌」（粘贴生成结果做对比反推参数）
- PWA 离线可用

## 5. 关键交互流程

### 5.1 调参主循环（核心）

```
用户拖动滑块
  → Pinia 更新 params[group][key]
  → ①预览层：脏标记 → WebGL uniform 更新 → 下一帧渲染
  → ②提示词层：参数 token 重新解析 → token 表 diff → 只更新变化的词条（带高亮动效）
  → ③HUD 层：数值读数更新（数字滚动动效）
```

三条链路**并行且互不阻塞**：提示词编译是纯计算（<5ms），可与渲染帧并行。

### 5.2 感知层的三级反馈

任何参数变动都必须给用户三层反馈，缺一不可：

| 层级 | 内容 | 位置 |
|---|---|---|
| **数值反馈** | 精确数值 + 单位（`f/1.4`） | 滑块右上角，等宽数字 |
| **语义反馈** | 「背景散开，奶油虚化」 | 滑块下方副标题（可折叠） |
| **视觉反馈** | 画面真的变了 | 画布 |

### 5.3 提示词面板的「来源可追溯」

这是本产品的差异化核心。提示词里每一个词条都可**溯源**：

- 鼠标悬停 `shallow depth of field` → 高亮「光圈 f/1.4」滑块，并显示该词条的完整解释
- 点击 → 展开该词条的参数映射链（`光圈 1.4 → 浅景深 → shallow depth of field`）
- 手动删除某词条 → 记录为「已排除」，该参数标注为「已被用户覆盖」

这让用户建立「参数 ↔ 语义 ↔ 提示词」的完整心智闭环，而不是在黑箱里抄词。

### 5.4 平台切换的行为

切换平台不是简单换模板，而是**重新编译**：

```
参数状态（平台无关）
   ├─→ 语义 token 表（平台无关，带 en/cn 双语 + 分类标签）
   │     └─→ 渲染器：MJ 语法 / SD 语法 / 中文视频平台语法
```

平台差异处理：

| 平台 | 特性 | 编译策略 |
|---|---|---|
| Midjourney | `--ar --style --v --chaos --stylize`，正文为英文逗号短语 | 英文 token 流 + 参数后缀，词序按「主体→动作→场景→光线→镜头→风格→画质」 |
| Stable Diffusion | 正/负提示词分离，支持 `(word:1.3)` 权重 | 英文 token 流，权重映射，负面词从参数反推 |
| 即梦 | 中文自然语言，无语法后缀 | 中文 token 流，描述性长句拼接 |
| 可灵 | 中文 + 运镜/时长/帧率，倾向「镜头语言」 | 中文 + 结构化视频参数块 |
| Veo / Sora | 自然语言段落，强调时序与声音 | 生成为连贯段落，而非逗号短语 |

## 6. 设计原则

1. **工具感优先于装饰** —— 深色底、克制的色彩、每一个像素都有信息量；不做无意义的动画。
2. **即时反馈不可延迟** —— 任何交互必须在 100ms 内给出视觉响应，否则用户会认为是坏的。
3. **术语必须解释** —— 专业术语是好东西，但对新手是墙。每个术语配一句人话。
4. **默认值要有观点** —— 默认参数组合应该已经「好看」，而不是中性的 0 值。
5. **不做死胡同** —— 任何参数滑动过程中都不应产生「坏了」的效果；极端值也要优雅降级。

---

## 7. 隐私与合规

- **全本地**：图片解码、渲染、提示词生成全部在浏览器完成，无任何网络请求（字体可自托管）。
- **不上传、不留存**：不写 localStorage 中的图片缓存；分享链接只编码参数，不含图片。
- 预设库为静态内置数据，标注来源与授权。
